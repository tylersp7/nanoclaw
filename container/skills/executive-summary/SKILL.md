# Executive Summary

When asked to summarize findings, reports, or pipeline outputs, use this structured format. Adapted from McKinsey's SCQA framework for concise, actionable summaries.

## Format (325–475 words)

### Situation
2-3 sentences establishing current state and context. What was examined and why.

### Key Findings
3-5 bullet points, each with a quantified metric:
- "[Metric]: [Finding] — [Significance]"
- Every finding MUST include a number, percentage, or measurable comparison
- If a metric is unavailable, state: "Data unavailable — [what would be needed to measure]"

### Impact Assessment
What these findings mean for the business/project:
- Revenue/cost implications (quantified when possible)
- Risk exposure
- Opportunity cost of inaction

### Recommendations
2-4 actionable items, each with:
- **Owner**: Who should act (Tyler, Andy, automated system)
- **Timeline**: When (today, this week, this sprint)
- **Expected result**: What success looks like

### Next Steps
Numbered list of immediate actions (max 5). First item should be the highest-leverage action.

## Rules
- No filler phrases ("It's worth noting that...", "As we can see...")
- Lead every section with the most important information
- Flag data gaps explicitly rather than omitting or assuming
- Use bullet points, not paragraphs, for findings and recommendations
- Numbers always include units and context (e.g., "85% uptime" not just "85%")
- Compare to baselines when available (e.g., "up from 72% last week")

## When to Use
- Notification batching summaries
- Daily/weekly digest outputs
- Pipeline final step reports
- Any time the user asks for a summary or briefing
- Scheduled task outputs that aggregate multiple data sources

## Tone
Direct and professional. No hedging language. State conclusions confidently, flag uncertainty explicitly.
